Methodology & Architecture

A brief overview of the key decisions behind the dashboard — what was chosen, why, and how the pieces connect.

🌐

Data Sourcing — RSS Feeds

Why RSS?
  • 50+ curated feeds chosen to cover systemic risk themes: macro (Reuters, FT, WSJ, NYT), regulatory (BIS, IMF, Federal Reserve, EBA), credit & private markets (PitchBook, Preqin), crypto (CoinDesk, CoinTelegraph) and cybersecurity (Krebs, Dark Reading).
  • RSS was chosen over web scraping because feeds are structured, lightweight and publisher-sanctioned — no rate-limiting, legal grey areas or fragile HTML parsing.
  • Each feed is fetched fresh on every pipeline run, so the dashboard always reflects the current news cycle rather than a cached snapshot.
→ Connects to: Article collection. Up to 20 entries per feed are extracted and truncated to 1,200 characters — enough context for AI analysis without token bloat.
↓
🧹

Data Cleanup & Filtering

Quality gate
  • Minimum length filter: articles under 50 characters are discarded — these are typically navigation labels or empty feed entries, not real content.
  • Field fallback: the pipeline tries summary → description → title in order, so even minimal feed entries contribute something meaningful.
  • Length capping at 1,200 characters keeps token usage predictable when text is later passed to the AI, and prevents one verbose article from dominating a topic cluster.
→ Connects to: Topic clustering. Clean, consistent text improves the quality of semantic grouping — garbage in, garbage out applies strongly to embedding-based models.
↓
🔬

Topic Clustering — BERTopic

Unsupervised AI
  • BERTopic was chosen because it discovers topics from the data itself — no predefined list of story types needed. This means the dashboard captures emerging narratives automatically.
  • Articles are converted into semantic embeddings (numerical representations of meaning) using a sentence-transformer model, then grouped by similarity using K-Means clustering into 15 topic buckets.
  • UMAP reduces those embeddings to two dimensions for the Intertopic Distance Map — topics that appear close together on the map share conceptual overlap.
  • The most representative articles from each cluster (closest to the cluster centre) are selected as inputs for the AI summarisation step.
→ Connects to: Claude AI. Only the 8 most central articles per topic are sent to Claude, keeping API calls focused and cost-efficient.
↓   (runs in parallel with theme scoring)
🏷️

Theme Scoring — Predefined Risk Themes

Supervised layer
  • 9 risk themes were manually defined to reflect the systemic risks most relevant to the intended use case: Inflation, Recessionary pressures, Private credit, AI, Cyber attacks, Commercial real estate, Consumer debt, Bank lending & credit risk, Digital assets.
  • Each theme has a short description that acts as a semantic anchor. Articles are compared to these descriptions using cosine similarity — a measure of how closely two pieces of text point in the same conceptual direction.
  • An article can match multiple themes simultaneously if its similarity score exceeds the threshold (0.15), reflecting the reality that news stories often span several risk categories.
  • Theme weights (e.g. Private credit = 1.2×, Digital assets = 0.7×) allow manual calibration of how prominently each theme is surfaced relative to raw volume.
→ Connects to: The heatmap. Theme scores are computed per article, then aggregated per topic cluster to produce the affinity percentages shown in the heatmap grid.
↓
✨

AI Summarisation — Anthropic API

Claude Haiku
  • Claude Haiku (claude-haiku-4-5) was selected for summarisation — it is fast, cost-efficient and capable enough for structured text generation tasks like this.
  • The model is given a structured prompt asking for a 3–5 word title, a 1–2 sentence overview, and key examples drawn only from the supplied articles — keeping outputs grounded and factual.
  • The API key is stored as an encrypted GitHub Actions secret (ANTHROPIC_API_KEY) and is never exposed in code or logs.
  • If a single topic call fails, the pipeline continues and falls back gracefully — the dashboard publishes with a placeholder rather than crashing entirely.
→ Connects to: Topic summaries table on the dashboard and the topic labels on the Intertopic Distance Map.
↓
🟦

Theme × Topic Affinity Heatmap

The connective layer
  • The heatmap is where the two analytical tracks meet: the unsupervised topic clusters (rows) are crossed with the supervised risk themes (columns).
  • Each cell shows the percentage of articles in that topic cluster that were also tagged with that risk theme — a simple but powerful way to see which stories are driving which risks.
  • A dark cell means strong association: e.g. a "central bank policy" topic cluster with a dark cell under "Inflation" confirms that topic is primarily an inflation story.
  • This layer was added specifically to bridge the gap between bottom-up discovery (what is being talked about?) and top-down risk monitoring (does it matter to us?).

Infrastructure — GitHub Actions & Pages

Zero server cost
  • GitHub Actions runs the entire pipeline on demand — it spins up a cloud machine, installs dependencies, runs the Python scripts, and shuts down. No always-on server is needed.
  • The pipeline is triggered by a Refresh button on the dashboard itself, which calls the GitHub API to launch a new run — putting control in the user's hands.
  • GitHub Pages hosts the static dashboard for free. After each run, the generated HTML files are pushed to a dedicated branch and served publicly.
  • Secrets (API keys) are managed by GitHub's encrypted secrets store — they are injected into the pipeline at runtime and are never written to any file or log.
End-to-end flow: Button click → GitHub API → Actions runner → Python pipeline → static HTML → gh-pages → live dashboard. Typical end-to-end time: ~5 minutes.
